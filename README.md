## 1. АРХИТЕКТУРА ПРОЕКТА И СТРУКТУРА ДИРЕКТОРИЙ

Проект построен по принципам ООП с использованием паттерна "Стейт-машина" (State Machine) для управления логикой игры, `pygame` для рендеринга и `pymunk` для физики.

```text
.
├── main.py                     # Точка входа. Управление окном, масштабированием и главным циклом.
├── generate_models.py          # Генерация OBJ-файлов в assets/models/.
├── core/                       # Базовые независимые подсистемы
│   ├── config.py               # Глобальные константы, палитры, размеры сетки и тайлов.
│   ├── camera.py               # Плавная камера с поддержкой эффекта тряски (screen shake).
│   ├── leaderboard.py          # Логика сохранения/загрузки рекордов (JSON).
│   └── recorder.py             # Захват экрана (FFmpeg, wf-recorder, wl-screenrec, OpenCV).
├── engine/                     # Игровой движок и механики
│   ├── asset_generator.py      # ПРОЦЕДУРНАЯ ГЕНЕРАЦИЯ ТЕКСТУР.
│   ├── asset_manager.py        # Синглтон для загрузки, кэширования текстур и хитбоксов.
│   ├── entities.py             # Игровые объекты: Player (с физикой Pymunk), RockEntity, Particle.
│   ├── level.py                # Процедурная генерация уровня (пещеры, спавн руды и камней).
│   └── ui.py                   # Адаптивный GUI (относительное позиционирование, UINode).
├── states/                     # Игровые состояния (наследуются от State)
│   ├── state_machine.py        # Базовый класс стейт-машины.
│   ├── menu_state.py           # Главное меню.
│   ├── play_state.py           # Основной игровой процесс. Интеграция Pymunk Space.
│   ├── skin_state.py           # Меню выбора скинов.
│   └── leaderboard_state.py    # Экран рекордов.
└── assets/                     # Генерируется автоматически при первом запуске
    ├── spritesheets/           # Сгенерированные .png файлы текстур.
    ├── data/                   # Сгенерированные .json файлы с метадатой (координаты кадров).
    ├── models/                 # OBJ-файлы (wall, dirt, rock, coin, player).
    └── saves/                  # Сохранения (leaderboard.json).

```

## 2. СИСТЕМА АССЕТОВ И ТЕКСТУР (ВАЖНО)

В проекте **не используются** заранее нарисованные текстуры. Все текстуры генерируются процедурно при первом запуске.

### Процесс генерации:

1. Точка входа `main.py` вызывает `AssetGenerator.generate_all()`.
2. Класс `AssetGenerator` (`engine/asset_generator.py`) отрисовывает поверхности (surfaces) через функции `pygame.draw`.
3. Отрисованные поверхности объединяются в спрайтшиты и сохраняются в папку `assets/spritesheets/`.
4. Одновременно генерируется JSON-файл в `assets/data/`, описывающий координаты каждого кадра в спрайтшите.
5. Во время игры `AssetManager` (`engine/asset_manager.py`) считывает JSON, вырезает нужные кадры из `.png` и кэширует их, а также динамически вычисляет пиксельные хитбоксы через `pygame.mask`.

**ПРАВИЛО ДЛЯ АГЕНТА:** Если необходимо добавить новую текстуру, анимацию или объект:

* **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО** просить пользователя скачать картинку.
* Напишите метод генерации в `AssetGenerator`.
* Сохраните метадату в виде словаря (описание кадров x, y, w, h).
* Добавьте вызов нового метода в `AssetGenerator.generate_all()`.

## 3. ФИЗИКА (PYMUNK) И СТОЛКНОВЕНИЯ

В игре используется библиотека `pymunk` для реалистичного скатывания камней и платформинга.

* **Типы коллизий (collision_type):**
* `1` — Статические тайлы (Стены, Земля). Добавляются в `PlayState` при старте.
* `2` — Камни (`RockEntity`). Круглые динамические тела.
* `3` — Игрок (`Player`). Прямоугольное тело без вращения (`moment = float('inf')`).


* **Обработка столкновений:**
* Состояние "на земле" или "на стене" у игрока вычисляется через `space.shape_query(player.shape)` и анализ нормалей контактов.
* Смерть от камня обрабатывается через `space.shape_query` и вычисление наносимого импульса при падении (или прижатии к стене) в функции `update` игрока.
* Если игрок выкапывает блок земли под камнем, статический тайл удаляется из `space`, и камень начинает падать в соответствии с гравитацией.

## 4. СИСТЕМА GUI (АДАПТИВНАЯ)

Все элементы UI (`UILabel`, `UIButton`, `UIPanel`) наследуются от `UINode`.
Система использует **относительное позиционирование** (`rx, ry, rw, rh`), где значения от `0.0` до `1.0` представляют проценты от родительского контейнера.
Выравнивание происходит по `ax` и `ay` (anchors). `0.5, 0.5` означает центрирование.
При масштабировании окна вызывается метод `layout(parent_rect)`, который пересчитывает абсолютные пиксельные координаты.

Оверлеи игрового экрана (паузa, смерть, победа) позиционируются относительно области игры (`pygame.Rect(0, PANEL_HEIGHT, CANVAS_W, CANVAS_H - PANEL_HEIGHT)`), а не всего холста.

**ПРАВИЛО ДЛЯ АГЕНТА:** При добавлении новых меню используйте только относительные координаты от `0.0` до `1.0`. Не хардкодьте пиксельные позиции.

## 5. ПРАВИЛА И ИНСТРУКЦИИ ДЛЯ КОДИНГ-АГЕНТОВ

При получении задачи на доработку/модификацию кода соблюдай следующие строгие правила:

1. **Не ломай ООП и инкапсуляцию:** Модифицируй конкретные классы. Не превращай классовые методы в глобальные функции.
2. **Пиши без комментариев и аннотаций:** Код должен быть чистым, pythonic. Никаких docstrings и # комментариев (если пользователь явно не попросил).
3. **Единый стиль Pymunk:** При создании новых физических объектов обязательно задавай `friction`, `elasticity` и `collision_type`. Не смешивай старую кинематику на векторах и новую динамику Pymunk.
4. **Безопасное удаление:** Если объект (земля) разрушается, он должен быть удален из массива рендера (`level.grid`) И из физического пространства (`space.remove`).
5. **Масштабирование окон:** Любой рендер должен производиться на `play_view` или `canvas`. Окончательный результат масштабируется на `screen`. Напрямую на `screen` ничего рисовать нельзя.
6. **Отсутствие хардкода:** Все цвета, размеры сетки, фреймрейт должны браться из `core/config.py`. Если нужен новый параметр — добавь его туда.
